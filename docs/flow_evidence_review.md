# 诊断流程发布证据审查

更新日期：2026-07-20

> 本文记录官方说明书证据、平台策略和发布状态。`published` 只表示当前步骤通过本次来源审查并已被后端加载，不表示海尔官方认可本第三方产品。

## 审查方法

- 对 `knowledge/raw/JH69U1_manual.pdf` 与 `VC35U1_manual.pdf` 执行按页文本提取。
- 渲染并目视检查关键页面，确认表格、图示和页面编号可读。
- 将每个步骤拆分为说明书依据、平台安全/隐私策略和产品结果确认交互。
- 说明书没有直接或部分证据的流程不得发布给普通用户。

## 为什么导航流程没有发布

VC35U1 说明书明确支持清理障碍物、擦拭传感器和维护轮刷，但没有直接建立“传感器灰尘或轮刷异物导致路径混乱/反复碰撞”的故障因果关系。

因此当前流程保留为 `draft`：

- 普通用户的诊断选项接口不会返回它。
- 创建 `navigation_abnormal` 会返回没有已发布流程。
- 后续只有取得海尔官方导航故障资料，或将其明确定位为经过受控验证的第三方基础检查流程，才允许发布新版本。

## 发布门禁

`backend/app/flow_catalog.py` 执行以下规则：

- 发布流程必须包含审核时间和审核标识。
- 步骤必须具有来源 URL、PDF 页码、证据等级和依据摘要。
- `evidence_level=none` 的步骤不能进入发布流程。
- 已发布或已停用版本不可原地修改。
- 修改发布内容必须创建更高版本；新版本发布时旧版本自动转为 `retired`。
- 已开始会话继续绑定原 `flow_id`，不会被新版本替换。

## 证据与策略分离示例

以 JH69U1 充电触点清洁步骤为例：

- 官方依据：维护前关机断电、不得湿擦充电弹片、清洁回充灯和触点灰尘。
- 平台安全策略：禁止用金属工具刮擦或短接触点。
- 产品交互：执行完成后只让用户反馈“已解决/未解决”。

平台策略不会伪装成说明书原文，这一边界由 JSON 字段 `evidence_basis` 与 `policy_note` 分别记录。
